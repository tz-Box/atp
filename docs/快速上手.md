# 快速上手：30 分钟跑通第一次评测

> 读者：第一次使用 ATP 平台的算法工程师。
> 目标：用一个**照抄即可跑**的最小例子，走通"算法仓 → 提交评测 → 看结果"全流程。
> 读完本文你再按需要深入：[算法接入手册](算法接入手册.md)（协议/SDK 细节）、
> [scenario.yaml Schema](scenario-schema.md)（配置参考）、[CI 集成](CI集成.md)（接 Hub 自动触发）。

## 0. 心智模型（30 秒）

```
你的算法仓库根目录 scenario.yaml   ← 你写的唯一必需文件：怎么启动你的算法 + 跑哪些场景
        │
        ▼
ATP 评测服务（已部署好，你不管）  ← checkout 你的仓 → 拉起你的算法进程 → 喂数据 → 打分
        │
        ▼
console 网页 / 报告              ← 你看结果的地方
```

**你的算法是黑盒**：ATP 按 manifest 拉起它，经消息通道喂观测帧，你的算法逐帧回结果，
checker 判 pass/fail。你不需要懂评测内部，只需实现"收帧 → 回结果"的协议（SDK 已封装，4 个钩子）。

## 1. 前置确认（2 分钟）

ATP 服务由团队部署在评测机上，你拿到两样东西即可使用：

| 你需要 | 从哪拿 | 用途 |
|---|---|---|
| 服务地址 `ATP_BASE_URL` | 评测负责人（如 `http://atp.turing-zero.com`） | 提交/查询评测 |
| 服务令牌 `ATP_SERVICE_TOKEN` | 评测负责人 | API 鉴权（console 网页也可飞书登录） |

验证服务可用：

```bash
export ATP_BASE_URL=http://atp.turing-zero.com   # 换成你的地址
export ATP_SERVICE_TOKEN=<找评测负责人要>
python3 -m autotest.client atp health
# 预期：{"ok": true, "version": "...", "tzcomm": true, "queue": 0}
```

> 没装 `tz_atp` 包？在 ATP 仓 `pip install --user -e .`；或直接用浏览器打开
> `<ATP_BASE_URL>/console`（飞书登录）跳过命令行。

## 2. 最小算法仓（5 分钟，照抄）

建一个目录（就是你的"算法仓"），只需两个文件：

```
my_algo/
├── scenario.yaml      # manifest：ATP 读它知道怎么测你
└── sut.py             # 你的算法进程（这里是回声示例）
```

**`scenario.yaml`**（5 行即可跑）：

```yaml
launch: "python3 sut.py"               # 启动命令（相对本文件目录执行）
consumes: ["pipe.slam.SlamObs"]        # 你消费的观测 schema（照抄，示例用合成 SLAM 数据源）
required_sensors: { lidar: [front] }   # 你需要的传感器实例（照抄）
hyperparams: {}                        # 超参默认值（先空着）
scenarios:
  - id: smoke                          # 场景 id（^[a-z0-9_]+$），Hub 勾选/手动触发都引用它
    description: 最小冒烟场景
    scenario: scenarios/smoke.yaml     # 场景文件（第 3 步创建）
```

**`sut.py`**（回声算法：收到里程计原样回传——协议最小完整实现）：

```python
from autotest.protocol import messages as msg
from autotest.protocol.schema import Pose, StampedPose, decode_observation, encode_result
from autotest.registry import load_plugin
from autotest.sdk import SutBase

load_plugin("pipe.slam")  # 注册 pipe.slam schema 编解码器

class EchoSlam(SutBase):
    module = "pipe.slam"

    def on_reset(self, testcase_meta):    # 每个 testcase 前：清状态、保模型
        pass

    def on_step(self, observation):       # 每帧观测 → 回结果
        data = decode_observation(observation["data"])  # SlamData
        pose = data.odom if data.odom is not None else Pose(0, 0, 0, 0, 0, 0, 1)
        return msg.Result(
            "pipe.slam",
            encode_result("pipe.slam.StampedPose",
                          StampedPose(timestamp=observation["timestamp"], pose=pose)),
        )

if __name__ == "__main__":
    EchoSlam("echo-slam").spin()
```

> 另有 4 个可选钩子：`on_init`（收 sensor_config+hyperparams）、`on_terminate`（回自统计）。
> 本例是开环（回 result）；闭环算法回 action，见 [算法接入手册](算法接入手册.md) §3.7。

**`scenarios/smoke.yaml`**（场景文件：评测内容本体——用什么数据、怎么判过）：

```yaml
body: pbox_v1                    # 本体资产（机器人传感器布置，ATP 内置）
dataset:
  type: pipe.slam.synthetic      # 合成数据源（零外部依赖，ATP 内置插件）
  config: { n_testcases: 2, n_steps: 30 }
checker: pipe.slam.ape           # 轨迹精度判定（回声算法应满分通过）
checker_config: { ate_threshold: 0.5, rpe_threshold: 0.05 }
sensor_config:
  lidar: { front: /points }      # 与 required_sensors 实例名对齐
```

> 场景文件字段全集见 [scenario.yaml Schema](scenario-schema.md) §4；
> 多场景、超参覆盖、runtime 声明等进阶写法见 §3/§5。现在照抄即可。

## 3. 提交评测（1 分钟）

**方式一：console 网页（推荐首次）**——浏览器打开 `<ATP_BASE_URL>/console`，
飞书登录后在"手动触发评测"表单填：

- repo：`/path/to/my_algo`（本地路径；或 `owner/repo` git 坐标）
- scenario：`smoke`（场景 id；留空 = 清单全跑）
- 点提交，下方评测列表实时刷新状态。

**方式二：命令行**：

```bash
python3 -m autotest.client atp submit --repo /path/to/my_algo --scenario smoke
# 预期：stderr 打 job_id，阻塞等待终态后输出 summary JSON
```

> 重复提交同一 `correlation_id` 是幂等的（返回 `duplicate: true`），安全重放不重复执行。

## 4. 看结果（2 分钟）

console 评测列表点任意一行展开详情；命令行 `atp status <job_id>`。关键字段：

```json
{
  "status": "success",                    // success / failure / running / queued
  "summary": "2/2 passed; tc-1: passed (ate_rmse=...); ...",
  "vs_baseline": {"new": 2}               // 与滚动基线对比（首次全记 new）
}
```

- `passed` 由 checker 按 `checker_config` 阈值判定；metrics（如 `ate_rmse`）进报告。
- 完整产物在评测机 `artifacts/<job_id>/`：`report.json`（逐 testcase 明细）、`session.log`（执行留痕）。
- 失败排查先看 summary 与 session.log——速查表见 [算法接入手册](算法接入手册.md) §4.4。
