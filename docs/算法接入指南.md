# SLAM 算法接入指南

本文档是 SLAM 算法接入评测服务的**唯一需求来源**。算法是黑盒，由评测服务拉起；数据源（rosbag/rostopic/device）与 GT/打分对算法透明。你只做三件事：**写 `scenario.yaml`、读环境变量、实现协议处理**。

---

## 1. 进程模型

```
算法仓库根目录 (scenario.yaml) ──读──> Autotest Service（常驻，框架）
                                          │ 拉起算法 + 注入环境变量
                                          ▼
                        算法进程（你的代码，黑盒）
                        ├─ 订阅 obs（收 STEP 帧）
                        ├─ 发布 result（回位姿）
                        └─ 响应 ctl 服务（init/reset/terminate）
```

- Service 由框架启动（`python3 -m autotest.server`），你不需要自己启动它。
- 你**不感知**场景/数据源/GT/checker：一切输入输出走协议。

## 2. 你要做的三件事

| # | 做 | 在哪 |
|---|---|---|
| 1 | 写 `scenario.yaml`（静态声明） | 算法仓库根目录，见 §3 |
| 2 | 进程启动读环境变量 `AUTOTEST_SESSION` / `AUTOTEST_TOPICS` | 见 §4 |
| 3 | 实现协议处理（握手 + 每帧回位姿） | 见 §5、§6 |

## 3. scenario.yaml（静态声明，取代"注册"）

```yaml
module: slam                    # 必须与评测场景的 module 一致
launch: "python3 main.py"       # 启动命令（相对本文件目录执行）
scenario: /path/to/scenario.yaml    # 建议评测场景（评测方可 --scenario 覆盖）
required_sensors:               # 可选：你需要的传感器实例，框架校验场景覆盖
  lidar: [front, rear]
  imu: [imu]
hyperparams:                    # 可选：经 INIT 下发
  map_resolution: 0.05
# image: registry.example/slam:v1   # 可选：docker+bind 运行则填镜像名
# output_topic: /xxx/result          # 可选：算法自有产物话题（仅记录）
```

## 4. 会话身份：环境变量（Service 注入）

| 变量 | 内容 |
|---|---|
| `AUTOTEST_SESSION` | 本次评测会话号（唯一，不要自己生成） |
| `AUTOTEST_TOPICS` | JSON：`{"obs", "result", "action", "ctl"}` 四个话题名 |

话题名**只从环境变量取**，不要硬编码前缀。

## 5. 协议与生命周期

所有消息是可 msgpack 的 dict：

```python
{"type": <类型>, "session_id": <会话号>, "payload": {...}, "seq": <可选帧序号>}
```

| type | 方向 | payload | 你回什么 |
|---|---|---|---|
| `init` | Service→你 | `{sensor_config, hyperparams}` | `ready` |
| `ready` | 你→Service | `{module, version, required_sensors}` | — |
| `reset` | Service→你 | `{testcase_id}` | `reset_ack{ok}` |
| `step` | Service→你 | `{done, observation}` | `result`（开环） |
| `terminate` | Service→你 | `{reason}` | `final` |

时序：`INIT→READY` 宣告能力 → 每个 testcase 先 `RESET`（**清状态、保模型**，同实例跨 testcase 复用）→ 逐帧 `STEP`，每帧异步回 `result` → 全部跑完 `TERMINATE→FINAL`。

- 指令走 `ctl` **service**（一问一答）；帧数据走 `obs` **topic**（不回确认）。
- **时钟以 STEP 的 `timestamp` 为准**，禁止读系统墙上时钟做算法时间（Service 可能加速/实时）。
- 一帧可回多个 result，也可攒多帧回一个，都行；结果异步发，不受 step 频率约束。
- `seq` 是 Service 推流的帧序号（0 起递增），丢帧排查用，你可忽略。

## 6. SLAM 数据格式

### 6.1 观测（`step` 的 `observation` = `{timestamp, module, data}`）

`data` 为 SlamData：

```json
{
  "sensors": {
    "lidar": {
      "front": {"shape": [N, 3], "dtype": "float32", "data": "<bytes>"},
      "rear":  {"shape": [N, 3], "dtype": "float32", "data": "<bytes>"}
    },
    "imu": {
      "imu": {"angular_velocity": [gx, gy, gz], "linear_acceleration": [ax, ay, az]}
    }
  },
  "odom": [x, y, z, qx, qy, qz, qw]
}
```

- `sensors` 是「类型 → 实例名 → 数据」；**每帧保证完整**（多实例经容差同步后到齐才产帧，IMU 取最近帧）。
- 点云还原：`np.frombuffer(data, dtype).reshape(shape)`（float32，(N,3)）。
- `odom` 可选（单值里程计）。

### 6.2 结果（`result` 的 payload = `{module, data}`）

位姿估计（默认）：

```json
{"timestamp": <float>, "pose": [x, y, z, qx, qy, qz, qw]}
```

管道中轴线（pipe 场景用 CylinderResult）：

```json
{"timestamp": <float>, "center": [cx, cy, cz], "direction": [dx, dy, dz],
 "valid": true, "straightness_residual": <float>, "radius": <float>}
```

## 7. 传感器声明与校验

场景提供 `sensor_config`（经 INIT 下发，实例名与观测里的实例名一致）：

```yaml
sensor_config:
  lidar: { front: /rslidar_points_front, rear: /rslidar_points_rear }
  imu:   { imu: /IMU }
```

你在 `scenario.yaml` 的 `required_sensors` 声明所需实例；框架校验场景覆盖，缺失则 fail fast（你会收到明确报错）。

## 8. 运行

```bash
python3 -m autotest.client run <算法仓库>/scenario.yaml [--scenario <场景.yaml>]
```

- 参数是**算法根目录的 scenario.yaml**；Service 按 `launch` 拉起你的进程并注入环境变量。
- `--scenario` 覆盖 manifest 里自选的场景（回归/交叉测试用）。

## 9. 需求清单（对照自检）

| # | 需求 | 位置 |
|---|---|---|
| R1 | 仓库根目录放 `scenario.yaml`，`module: slam`，`launch` 指向启动命令 | §3 |
| R2 | 启动时读 `AUTOTEST_SESSION` / `AUTOTEST_TOPICS`，话题名不硬编码 | §4 |
| R3 | 响应 `init`→回 `ready{module, version, required_sensors}` | §5 |
| R4 | 响应 `reset`→回 `reset_ack`；**清运行状态（位姿/地图/缓存），保留模型参数** | §5 |
| R5 | 响应 `step`：解析 `observation.data`（SlamData），每帧回 `result` | §5、§6 |
| R6 | 响应 `terminate`→回 `final`，可带自统计 | §5 |
| R7 | 时钟用 STEP 的 `timestamp`，不读墙上时钟 | §5 |
| R8 | 一切输入输出走协议；不读场景 YAML、不访问数据集/GT/checker | — |
| R9 | 实例名（front/rear/imu）与 `sensor_config`/`required_sensors` 保持一致 | §7 |
